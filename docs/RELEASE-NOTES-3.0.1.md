# AnOOPlan 3.0.1 — патч: запуск на Android 15 и актуальный учебный проект

Дата: 2026-11-24. Версия **3.0.1**, `androidVersionCode` **50**.

**APK:** `AnOOPlan-3.0.1.apk` · Android 7.0+ (minSdk 24, targetSdk 35) · разрешение только `VIBRATE`,
`INTERNET` нет · сертификат не менялся — обновление ставится поверх 3.0.0.

Патч по итогам первой проверки релизного APK на локальном эмуляторе (AVD AnOOPlan35,
Android 15): эмулятор сразу поймал критичный баг запуска и подтвердил исправление.

## Исправлено

- **Белый экран при запуске на Android 15.** `NativeBridge.isTrustedOrigin()` вызывал
  `webView.getUrl()` с потока JavaBridge, а методы WebView принимают вызовы только из
  главного потока: Android 15 бросал RuntimeException, веб-часть получала «Uncaught Error»
  при инициализации, и приложение оставалось пустым белым экраном. Теперь URL страницы
  мосту передаёт `WebViewClient.onPageStarted` (главный поток); прямых обращений к WebView
  из моста больше нет. Проверка origin сохранена для всех действий моста.
- **Устаревший учебный проект заменяется актуальным.** Копия «Учебного проекта», сохранённая
  версией без цен кабелей и сечений КНС, заполняла «Ведомости» замечаниями. Теперь такая
  копия распознаётся (имя + проверки движка) и заменяется свежей — при восстановлении
  черновика и при открытии из списка проектов. Рабочие проекты с другими названиями не
  затрагиваются. На GitHub Pages исправление уже развёрнуто.

## Проверки

- 561 юнит-тест (560 pass, 1 штатный skip), `tsc`, ESLint — зелёные; CI, CodeQL, Gitleaks — success.
- Регрессионные тесты: «проверки демо-проекта проходят без замечаний» (`validateProject` +
  `domainWarnings`), сценарий обновления устаревшей копии, страж против `webView.getUrl()`
  в мосте (`tests/webview-security.test.ts`).
- Эмулятор Android 15: приложение рендерится, учебный проект — «Структурных замечаний
  не найдено», заполнение лотков рассчитано по всем сечениям.

  build-tools 35 в `tools/build-tools-win/35.0.0`, запуск — `bash scripts/build-apk.sh`
