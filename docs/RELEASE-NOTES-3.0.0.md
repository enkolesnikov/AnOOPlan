# AnOOPlan 3.0.0 — «Поле и надёжность»

Дата: 2026-11-23. Версия **3.0.0**, `androidVersionCode` **49**.

**APK:** `AnOOPlan-3.0.0.apk` · Android 7.0+ (minSdk 24, targetSdk 35) · разрешение только `VIBRATE`,
`INTERNET` нет · сертификат не менялся.

Третья мажорная версия закрывает три темы: данные не потеряются даже при чистке хранилища
браузером, план не тормозит на проекте в тысячи объектов, а на объекте приложением можно
работать одной рукой в перчатках. Плюс диагностика без сети и разбор самого большого
файла кодовой базы.

## Что нового

### Надёжность данных

- **Список проектов переехал в IndexedDB** (`src/project-store.ts`). Раньше все проекты лежали
  одной JSON-записью в localStorage: при переполнении 5 МБ терялось всё сразу, а система
  могла зачистить localStorage без предупреждения. Теперь каждый проект — отдельная запись
  в IndexedDB; старые данные переносятся автоматически при первом запуске (миграция с
  страховочной копией `cableplan:projects.migrated`).
- **Запрос постоянного хранилища.** При старте приложение просит `navigator.storage.persist()`:
  браузер/WebView перестаёт вычищать данные приложения под давлением памяти.
- **Авто-экспорт страховочной копии.** Каждое 10-е ручное сохранение дополнительно скачивает
  файл `.anooplan` — полную копию проекта, которую можно открыть на другом устройстве.
  Счётчик — на проект, сбрасывается после каждого авто-экспорта (`src/auto-backup.ts`).
- Индикатор квоты и размер проекта — на экране «О программе» (см. ниже).

### Скорость плана

- **Culling по видимой области** (`src/plan-culling.ts`). SVG-оверлей больше не рисует все
  объекты проекта: в DOM попадают только сегменты, размеры, оборудование и пины в кадре
  (плюс допуск на размер символов). Выбранные объекты и выбранный кабель не отсекаются.
  На бенчмарке 2000 сегментов в DOM остаётся **60 сегментов, ~1100 узлов вместо ~10 000** —
  панорама и ввод перестают фризить.

### Полевой режим

- Включается из боковой панели («🧭 Полевой режим») и запоминается между запусками.
- Крупные сенсорные цели (минимум 48 px), нижняя панель из 4 действий:
  выбор, замечание, оборудование, трасса — всё под большим пальцем.
- **Быстрый пин с фото:** в полевом режиме создание замечания сразу открывает камеру,
  а система даёт короткое виброподтверждение.
- Тёмная «уличная» тема с высоким контрастом — читается на солнце.
- Фиксация портретной ориентации (где WebView её поддерживает).

### Диагностика без сети

- Экран «О программе» показывает версию и движок WebView, объём занятого хранилища
  (оценка квоты), размер текущего проекта и счётчики объектов.
- Кнопка «Скачать отчёт» выгружает текстовый диагностический файл: версия, среда,
  хранилище, размер проекта — всё, что нужно для обращения, без единого сетевого запроса.

### Техдолг

- `export-pdf.ts` (1222 строки) разбит на три модуля: `src/pdf/pdf-model.ts` (типы,
  константы листа, текстовые утилиты), `src/pdf/pdf-sections.ts` (данные разделов),
  `src/pdf/pdf-renderer.ts` (отрисовка). Точка входа осталась фасадом (~120 строк),
  публичный API не изменился — тесты печатных форм проходят без правок.
- Декомпозиция `MainActivity.java` (642 строки) **отложена**: без локального JDK и эмулятора
  правки Java-кода непроверяемы, рисковать релизом нельзя. Пункт остаётся в дорожной карте.

## Проверки

- 559 юнит-тестов (558 pass, 1 штатный skip), 11 E2E (Playwright, Chromium) — зелёные.
- Перф-бенчмарк 2000 сегментов: culling подтверждён (60/2000 в DOM); полный прогон
  drag/ввод — ручной замер, в CI не входит.
- Бюджеты: JS 497,7 КБ из 600, CSS 45,8 КБ из 60; покрытие — на уровне 2.10.1.
- `knip` в CI; локально на Windows не стартует (лимит 2-ГиБ ArrayBuffer в Node 24).

## Известные ограничения

- Сценарий «сбой → восстановление» на эмуляторе и локальная сборка APK не проверялись
  (на машине разработки нет JDK/Android SDK): APK собирает и подписывает
  `android-release.yml` в CI, установку на устройство проверяет владелец.
- Codacy-покрытие ждёт токен владельца (как и в 2.10.x).
