# Независимый аудит AnOOPlan 2.9 (main, 2.9.0-dev)

Дата: 19 ноября 2026 г.
Ветка: `main`, исходный срез `7cacd08` (2.8.5), проверки — по текущему дереву с коммитами аудита.
Продукт: офлайн-приложение для раскладки кабельных трасс (Android WebView + веб-версия).
Источник: `github.com/enkolesnikov/AnOOPlan`.

## 1. Резюме для владельца

AnOOPlan остаётся зрелым офлайн-продуктом: данные, расчёты и документы считаются на устройстве, APK не
запрашивает `INTERNET`, а инженерный контур (юнит-тесты, смоук, E2E, визуальные эталоны, бюджеты) сильнее,
чем у большинства приложений этого размера. Свежий аудит не нашёл ни одного дефекта класса «приложение
не запускается» или «проект нельзя открыть», но нашёл несколько путей, где **данные или деньги могли
измениться молча**:

1. **Удаление этажа стирало фотографии в обход undo.** Это остаток F-02: ссылка восстанавливалась,
   а файл уже удалён. Закрыто (`392bbf1`).
2. **GC одной вкладки удалял вложения проекта, открытого в другой.** Несохранённый проект в соседней
   вкладке не входил в живые ссылки. Закрыто (`989835b`).
3. **Вставка вершины удваивала фиксированный запас сегмента** (14,5 → 15,0 м), **объединение трасс
   теряло тип/сечение второй**, а **разворот трассы ломал кабель на стыке двух трасс** (демо Л4:
   27,95 м → `null`). Все три закрыты (`0de4c5f`).
4. **PDF-оглавление обрезалось после ~17 пунктов**, а **примечание к плану разрывало заголовок и
   изображение** по разным листам. Закрыто (`b454fbb`).
5. **Серверное восстановление молча теряло фотографии и не проверяло манифест.** Теперь фото
   сохраняются локально, серверная ветка честно отклоняет фото, а SHA-256 манифеста проверяется до
   записи (`7419bed`).
6. **LAN-режим после введения токена был неработоспособен из браузера.** Добавлены cookie-токен из
   ссылки сервера, ввод через `?token=`, авторизация до разбора 80 МБ JSON (`7419bed`).

Итог: **15 коммитов** с исправлениями и тестами, **319 юнит-тестов** (было 294), все проверки зелёные.
Остались в основном оптимизации больших проектов (перетаскивание, пересчёт на каждый символ), редкие
крайние случаи спецификации/оценки по сечениям и серверный режим. Они вынесены в ROADMAP с оценками,
а не замаскированы.

## 6. Честные остатки (не имитируют «всё закрыто»)

1. **Большие проекты** (200 кабелей/2000 сегментов) всё ещё 느зки при drag и вводе: 90–100 мс на
   событие. Это архитектурная правка (ref/rAF для drag, единый индекс сегментов, totals из cableCalcs),
   оценка M–L; вынесена в 2.9.1/3.0.
2. **Смешанные сечения и цены по `size`**: спецификация уже разделяет типы, но цена по сечению и смета
   «Лотки» одной строкой остаются. Нужен матчинг `size` и отдельные строки сметы; M.
3. **Углы после split/стояка** и **подбор сечения по неполным данным** — корректность спецификации;
   M–S.
4. **Серверный режим** остаётся вспомогательным: фото хранятся в браузерном IndexedDB, GC серверных
   проектов не реализован, `.anooplan` с `idb:`-id требует отдельного remap. Для APK/Pages это не путь
   пользователя; зафиксировано.
5. **F-11** (проекты одной записью localStorage, base64→Java, `persist()`) смягчён лимитами, но не
   закрыт: миграция в IndexedDB — 3.0.
6. **Android-полевой тест**: сборка APK проверена, установка на физическое устройство и реальный
   WebView — за владельцем.

## 8. Критерии приёмки исправлений

- **Данные:** удаление/undo любого объекта не трогает Blob; GC не удаляет вложения несохранённого
  проекта из другой вкладки; битый список не перезаписывается.
- **Расчёты:** split не меняет итог кабеля; merge разнотипных трасс отклоняется; реверс одной трассы
  не меняет метраж кабеля на другой; неизвестная высота даёт `null`, а не 0.
- **Экспорт:** TOC содержит все разделы; заголовок и изображение плана на одном листе; CSV-числа
  с запятой; растр не превышает бюджет.
- **Безопасность:** LAN без токена не отвечает; restore без манифеста/с фото отклоняется; APK без
  `INTERNET`.
- **Проверки:** `npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run coverage`, `npm run size`,
  `npm run smoke`, E2E, визуальные эталоны, сборка APK — зелёные.
