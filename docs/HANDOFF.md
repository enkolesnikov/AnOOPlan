# Контекст-хендофф: AnOOPlan

Документ для продолжения работы в новой сессии. Прочитайте его целиком перед первым действием.
Секретов здесь нет: токены и пароли передаются отдельно и в репозиторий не попадают.

## Что это за проект

**AnOOPlan** — приложение для раскладки кабельных трасс по PDF-планам здания и расчёта кабельного
журнала. Основной продукт — **офлайн-APK для Android**; та же кодовая база собирается как веб-версия
на GitHub Pages. Выросло из веб-приложения [ooplan](https://github.com/enkolesnikov/ooplan) (CablePlan).

- Репозиторий: <https://github.com/enkolesnikov/AnOOPlan>
- Релизы с APK: <https://github.com/enkolesnikov/AnOOPlan/releases>
- Сайт: <https://enkolesnikov.github.io/AnOOPlan/> — лендинг с возможностями и скриншотами.
- Веб-версия: <https://enkolesnikov.github.io/AnOOPlan/app/> — та же сборка, что и APK; публикуется
  автоматически при изменениях приложения (ручной `workflow_dispatch` сохранён).
- Текущая версия: **3.1.0**, versionCode 51, `com.anooplan.app`, minSdk 24, targetSdk 35.
  WebView 98+, **562** юнит-теста + смоук happy-dom + 11 E2E + замер perf 2000 сегментов.
- Возможности: PDF-планы и калибровка, оборудование с иконками и цветом, трассы, кабели и автопрокладка,
  журнал, справочник цен и смета с коммерческим предложением, печатные формы (титул, оглавление,
  штамп ГОСТ, лист изменений), печать выбранных разделов, обмен PDF/XLSX и проектом `.anooplan`,
  XLSX/PDF, история версий, фото, пины-замечания с фото, проверка заполнения КНС,
  типы КНС (лоток, гофра, труба, кабель-канал) с цветами, схема трасс с метражом гофры
  и углами коробов, относительные размеры между оборудованием, спецификация КНС с подсистемами
  СКС, артикулами/производителями и подбором стандартного сечения.
- **Курс — Android-first.** Облако — в планах (дальняя перспектива); приложение полностью офлайн,
  разрешение `INTERNET` не запрашивается, сетевых модулей нет.
- **Удобство:** поиск и фильтры по спискам (`Ctrl+K`), дублирование объектов (`Ctrl+D`), undo по
  действиям с подписями, горячие клавиши, мультивыбор и массовые действия, контекстные меню,
  порционная отрисовка больших списков; на телефоне сайдбар прокручивается и не ломается при клавиатуре.
- **Доступность:** системный размер шрифта Android (textZoom 85–160 %), тёмная тема, высокий контраст,
  reduced-motion; бюджет памяти рендера плана — 8 Мпикс с предупреждением.

### Ключевые решения (не пересматривать без причины)

1. **WebView вместо Kotlin-переписывания.** Одна кодовая база для сайта и APK, 394 теста, быстрые
   итерации. Kotlin оправдан только при ежедневной работе пером и листах A1+ — тогда начинать
   с порта `engine.ts` в KMP, а не с UI.
2. **Статика отдаётся по origin `https://appassets.local/`** через `AssetServer.shouldInterceptRequest`.
   На `file://` не работают IndexedDB и `crypto.randomUUID()`. Запросы `/api/*` получают 404 →
   включается `staticMode`.
3. **Всё офлайн.** Разрешение `INTERNET` не запрашивается. Никаких сетевых вызовов в APK нет.
4. **Экспорт на клиенте.** XLSX и PDF собираются на телефоне; печать — `PrintManager` с готовым PDF
   в спулер без растеризации. Файлы сохраняются через MediaStore, без опасных разрешений.
5. **Подпись.** `keystore/anooplan.jks` (в `.gitignore`), пароль в `keystore/pass.txt` (0600, вне git).
   Пароль не хранится в скриптах; `scripts/build-apk.sh` читает `keystore/pass.txt` или `KS_PASS`.
   GitHub Secrets: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KS_PASS`, `ANDROID_KS_ALIAS`,
   `ANDROID_CERT_SHA256`.
   **Важно:** в сессии 2026-10 на VPS сгенерирован новый ключ (оригинальный в репозиторий не входит).
   APK с 1.6.1 подписаны им; обновление поверх 1.6.0 требует переустановки (сначала сохранить проект
   в JSON). Если появится оригинальный keystore — положить его в `keystore/anooplan.jks`, заменить
   пароль и пересобрать релиз.
   **RuStore (2026-11-24):** подготовлены `keystore/rustore/pepk_out.zip` и
   `keystore/rustore/uploadcert.pem`; владелец подтвердил их загрузку в RuStore 2026-11-24.
   Повторно загружать файлы подписи для следующих версий не нужно. PEPK ZIP содержит зашифрованный
   существующий ключ приложения и его сертификат с SHA-256
   `6431374cf6a7d385c4c47f0f2bf54fcb5ee5b2c7120f057b18c4062af92fe097`.
   Для AAB создан отдельный `keystore/rustore/upload.keystore`, alias `upload`, RSA 2048; пароль —
   `keystore/rustore/upload-pass.txt` (0600, вне git), SHA-256 upload-сертификата —
   `ac3bdf0c8ef8cffa8d6efb30084de642d4ba8755bdbe10d191666e51f8f8b65a`. Все AAB для RuStore
   подписывать только этим upload key и не пересоздавать его. Основной ключ приложения не менять:
   RuStore будет подписывать им APK после загрузки AAB. Подтверждённая загрузка файлов подписи не
   означает загрузку AAB, прохождение модерации или публикацию приложения. AAB-сборка добавлена:
   `bash scripts/build-aab.sh`
   собирает `build/AnOOPlan-<версия>.aab` через aapt2 + bundletool без Gradle и подписывает его

   `bundletool validate` пройдены; формирование universal APK проверено, установка на устройство
   в этой задаче не выполнялась.

   `ACTIVE`, то есть опубликована; версия 3.0.1 (versionCode 50, versionId `2064976383`) —

6. **Автобэкап выключен** (`allowBackup="false"`): проекты могут содержать планы заказчика.
   Перед переустановкой/удалением приложения пользователь должен сохранить JSON-копию.
7. **История и GC.** Снимки проектов (до 20 на проект) лежат в IndexedDB. Фоновый GC удаляет
   PDF/фото, на которые больше не ссылаются текущий проект, undo/redo, сохранённые проекты и снимки.
   Снимки удалённых проектов тоже вычищаются.
8. **Заполнение лотка (1.15.0).** Считается по площади: `Sкаб = crossSectionMm2` или `π·d²/4`,
   `Sлотка = trayAreaMm2` или `trayWidthMm·trayHeightMm`, заполнение сегмента =
   `Σ(Sкаб · quantity) / Sлотка · 100`. Площадь всегда приоритетнее диаметра/размеров; неизвестные
   данные дают `null`/«не рассчитано», а не 0. Пороги: > 40 % — внимание, > 50 % — превышение.
   Размеры лотка — на трассе (не на сегменте): все сегменты трассы используют один лоток.
   `specifications().trayFill` — одна строка на сегмент для ведомости/PDF/XLSX/CSV.
9. **Иконки и цвет оборудования (1.16.0).** Иконка выводится из типа: `equipmentIcon(type)` ищет
   «камер/шкаф/розет/коммутатор/считыв», иначе — универсальный маркер. Геометрия `EQUIPMENT_ICON_GLYPHS`
   в системе 24×24, заливка цветом с `fill-rule="evenodd"` (отверстия объектива/окна/гнёзд — сквозные);
   один набор используется в `App.tsx`, списке объектов и `plan-svg.ts` (PDF-лист «План»).
   `Equipment.color` — необязательный `#rrggbb`; `equipmentColor()` при невалидном/пустом значении берёт
   цвет по умолчанию для типа (`EQUIPMENT_ICON_DEFAULT_COLORS`), значит подмена безопасна и видима.
   Миграции нормализуют цвет (`#rgb` → `#rrggbb`, мусор → `undefined`), API отклоняет мусор с 422.
10. **Справочник цен и смета (1.17.0).** Справочник (`Project.catalog`) — часть проекта, а не глобальный
    файл: поэтому он входит в JSON-копию, снапшоты и офлайн-хранилище, и старые снимки сохраняют свои
    цены (смена прайса не пересчитывает историю). Смета: оборудование — количество по модели × цена;
    кабели — итоговые метры × количество × цена (ручная `pricePerMeter` приоритетнее справочника по
    марке); лотки — длина по типу трассы × цена; работы — `laborPercent` % от материалов; итог =
    материалы + работы. Любая неизвестная цена/величина делает строку, раздел и итог `null` с пометкой
    «неполная смета» — неизвестное не подменяется нулём. Дата прайса (`catalogDate`) печатается в смете
    и КП. Схема осталась v2: новые поля необязательны и нормализуются при загрузке.
11. **Печатные формы и обмен (1.18.0).** PDF-документ начинается с титульного листа и «Оглавления»
    (страницы оглавления заполняются после рендера по фактическим номерам), на каждой странице кроме
    титула — упрощённый штамп по ГОСТ 2.104, в конце — лист регистрации изменений из
    `Project.document.changeLog`. `buildJournalPdf({ include })` печатает только выбранные разделы;
    титул и оглавление — всегда. Проект можно отдать одним файлом `.anooplan`
    (`src/project-file.ts`): JSON с проектом, PDF и фото; старые backup-копии тоже открываются.
    Обмен — через нативный `ACTION_SEND` и собственный `ShareProvider` (сборка без androidx);

15. **Скриншоты на каждый релиз: 1–3 (минимум один).** Прикладывать к GitHub Release (assets/описание)

16. **Шрифты — сабсеты и переименование (2.1.0).** В репозитории лежат сабсеты PT Sans

    стрелки, математика. OFL требует не использовать Reserved Font Names «PT Sans»/«ParaType» для
    модификаций — поэтому семейство переименовано; атрибуция и полный OFL остаются в «О программе».
    Редкие/экзотические глифы в сабсет не входят — это осознанный компромисс ради размера APK.
17. **XLSX — официальная сборка SheetJS (2.1.0).** В `package.json` `xlsx` указывает на tarball
    `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`: в npm-реестре 0.18.5 с high-уязвимостью
    без фикса. `npm ci` требует сети к cdn.sheetjs.com; API совместим, тесты XLSX проверяют запись
    и чтение обратно.
18. **Серверный экспорт удалён (2.1.0).** `server/export.ts` и `pdfkit` больше не существуют:
    локальный сервер (`npm start`) хранит проекты, а CSV/XLSX/PDF собираются на клиенте в обоих
    режимах. Не возвращать второй PDF-движок — это дублирование и класс ошибок с системными TTF.
19. **Бюджеты и статус в репозитории (2.1.0).** `npm run coverage` (93/85/92 %), `npm run size`
    (JS ≤460 КБ, CSS ≤40 КБ), `npm run status`/`status:full`. CI падает при регрессии покрытия или
    бандла; счётчики в документации не правятся вручную — их печатает `npm run status`.
20. **Типы КНС и цвета (2.2.0).** `Route.type` остаётся свободной строкой, готовые типы распознаются
    в `src/route-kinds.ts` по подстрокам (лоток/гофр/труб/кабель-канал/короб); схему под это не менять.
    `Route.color` — необязательный `#rrggbb` (мусор при загрузке отбрасывается, API — 422). Цвет по
    умолчанию задаёт тип; на плане он передаётся CSS-переменной `--route-color`, поэтому состояния
    «выбран/выбран кабель» работают как раньше. Для гофры и трубы диаметр хранится в `trayWidthMm`,
    площадь — π·d²/4; явная `trayAreaMm2` приоритетнее. Не заводить отдельные поля под каждый тип.
24. **Спецификация КНС и подсистемы (2.4.0).** `specificationKnS` агрегирует трассы по подсистеме,
    типу и сечению; углы входят в строку только для кабельных каналов/коробов. Артикулы/производители
    берутся из справочника цен (kind `tray`) без сетевой БД; `series`/`size` хранятся в модели, в UI
    редактируются артикул и производитель. Подбор сечения — по фактическому заполнению и диаметру
    кабелей, стандартные ряды, заполнение ≤40 %; фитинги по-прежнему не считаются.
25. **Сегментные размеры КНС (2.5.0).** `Segment.trayWidthMm/trayHeightMm/trayAreaMm2` — необязательные
    переопределения; наследуются **поле в поле** от трассы (`effectiveSectionDims`), а не «сечение целиком»:
    так можно задать только ширину или только диаметр. Площадь (`trayAreaMm2`) приоритетнее размеров;
    некорректное заданное значение даёт `incomplete`, а не 0. Предупреждение «неверное сечение» печатается
    на трассу один раз (для сегментов без override) или на конкретный сегмент. Схема проекта не менялась:
    миграция нормализует строки/мусор, API отклоняет 0 и отрицательные (422). В спецификации КНС метраж
    группируется по эффективному сечению; углы коробов относятся к основному сечению (наибольший метраж),
    чтобы не задваиваться. Подбор сечения трассы не учитывает сегменты со своим сечением — для них есть
    `suggestSegmentSection`. Не заводить отдельные «лотковые» подтипы и не переносить размеры в кабель.
26. **Доступность (2.5.0).** Android WebView не применяет системный «Размер шрифта» сам: `MainActivity`
    читает `Configuration.fontScale`, округляет и зажимает в 85–160 %, вызывает `setTextZoom`; эталон —
    `resolveTextZoom` в `src/a11y.ts`, тест сверяет Java и TS. `fontScale` остаётся в `configChanges`,
    и `onConfigurationChanged` повторно вызывает `setTextZoom` — крупный шрифт применяется без
    перезапуска. Тёмная тема — только `prefers-color-scheme` (без ручного переключателя), причём
    WebView берёт схему из **темы приложения**: со светлым `Theme.Material.Light` ночной режим
    игнорировался (проверено на Android 15). Поэтому объявлен `android/res/values-night/styles.xml`
    с тёмным `AppTheme`, а `uiMode` убран из `configChanges` — смена темы пересоздаёт Activity.
    Высокий контраст — `prefers-contrast: more`/`forced-colors`, анимации отключаются
    `prefers-reduced-motion` (это поведение было и до 2.5.0). Крупный текст переносится, интерактивные
    элементы используют `min-height`. План остаётся белой «бумагой» в обеих темах.
27. **Память рендера плана (2.5.0).** Бюджет 8 Мпикс (≈32 МБ RGBA) вместо 12; клип A1/A0 по видимой
    области, canvas-стороны округляются вниз, чтобы не превысить бюджет. Если лист не влезает,
    `planMemoryWarning` показывает баннер с мегапикселями и советом «Вписать» — тихое понижение качества
    недопустимо. Приоритет — стабильность WebView, а не максимальная резкость клипа.
28. **Инженерный долг (2.5.0).** Общие фикстуры — `tests/fixtures.ts`; ESLint flat-конфиг и `npm run lint`
    в CI; `npm run coverage` пишет lcov, CI загружает его в Codacy при наличии секрета
    `CODACY_PROJECT_TOKEN` (владельцу нужно добавить project token; без него шаг пропускается).
    Декомпозированы `sidebar.tsx` и `estimate-screen.tsx`; остальные сложные методы — 3.0.0.
23. **Схема трасс и относительные размеры (2.3.0).** Углы — это количество изменений направления
    трассы; для кабельных каналов/коробов они показываются в схеме. Фитинги и крепления по решению
    владельца не считаются. Размеры хранятся ссылками на оборудование (`Dimension.fromId/toId`),
    считаются по прямой на одном этаже и пересчитываются при перемещении; для разных этажей — ошибка.
    Схема трасс — табличная (PDF/XLSX/CSV), без отдельного графического чертежа.
22. **Страница этажа и PDF (2.2.1).** `floor.page` должна существовать в исходном PDF: иначе оверлей
    не наносится, `capturePlanPages` возвращает понятное предупреждение, а на лист PDF печатается
    note. Демо-PDF одностраничный — оба демо-этажа используют страницу 1. Не «понижать» страницу
    молча: это скрывает несоответствие плана.
21. **Ориентир nanoCAD BIM СКС (2.2.0+).** Из САПР СКС берём только полезное для мобильного приложения:
    типы КНС (лоток/труба/короб + гофра), цвета, расчёт сечений, отчёты. В 2.4.0 уже сделаны подсистемы
    СКС, артикулы/производители и спецификация КНС. Фитинги/крепления по решению владельца **не**
    считаются; остаются углы коробов. Кандидаты на 2.5.0 — сегментные размеры КНС, межэтажные размеры.
    DWG/IFC/САПР-платформа не нужны — продукт Android-first.

Android-инструменты; JDK на VPS уже установлен. Если `keystore/` нет, обычная сборка остановится:
ключ не должен генерироваться случайно. Первая локальная сборка без ключа:
`ALLOW_NEW_KEYSTORE=1 bash scripts/build-apk.sh` — создаст новый ключ и `keystore/pass.txt`.
Для существующего продукта это означает новую подпись и переустановку у пользователей.

Сборка на VPS уже подготовлена: JDK 17, Android SDK в `/root/android-sdk`, build-tools 35 в
`tools/build-tools/35.0.0`, platform jar в `tools/android.jar`, AVD `AnOOPlan35`, Chromium Playwright
в `~/.cache/ms-playwright`. `adb` — `/root/android-sdk/platform-tools/adb`.

**Локальная сборка APK на Windows** (с 2026-11-23, проверена на 3.0.0 — подпись тем же ключом,
что в CI): JDK Temurin 21 в `C:\Users\x4k3r\devtools\jdk-21.0.13.1+2`, Windows build-tools 35.0.0
в `tools/build-tools-win/35.0.0` (скачаны с dl.google.com; `d8`/`apksigner` — bash-обёртки поверх
`lib/d8.jar` и `lib/apksigner.jar`), zip-шим в `C:\Users\x4k3r\devtools\bin\zip` (Info-ZIP под
MSYS не завёлся; шим эмулирует `zip -q -X -0` через `python3 zipfile`). Запуск:

```bash
export PATH="/c/Users/x4k3r/devtools/jdk-21.0.13.1+2/bin:/c/Users/x4k3r/devtools/bin:$PATH"
export BUILD_TOOLS_DIR="$PWD/tools/build-tools-win/35.0.0"

```

Тонкости Windows: `npm run build:apk` под MSYS теряет node-шим — запускать скрипт напрямую через
`bash`; `ANDROID_JAR` обязан быть ASCII-путём (aapt — narrow C++ API, на кириллице «Illegal byte
sequence»; то же для финального `aapt dump` — скрипт дампит по ASCII-копии); javac получает
@-файл с Windows-путями в кавычках (`cygpath -m`); d8 вызывается массивом `D8_ARR` (путь с
пробелом «Рабочий стол») и получает классы JAR-ом — каталоги d8 не принимает («Unsupported
source file type»). Не создавать в `tools/build-tools-win/35.0.0` файлы `aapt`/`zipalign` без
расширения: MSYS считает их тем же файлом, что и `.exe`, и затирает бинарь.

**RuStore — постоянный канал публикации. Для каждой RuStore-версии обязателен AAB** (APK остаётся
форматом GitHub Releases, но не заменяет AAB для RuStore). Порядок на Windows:

```bash
export PATH="/c/Users/x4k3r/devtools/jdk-21.0.13.1+2/bin:/c/Users/x4k3r/devtools/bin:$PATH"
bash scripts/build-aab.sh
```

Скрипт берёт версию/`versionCode` из `package.json`, собирает `build/AnOOPlan-<версия>.aab` через
aapt2 + bundletool без Gradle, подписывает его существующим `keystore/rustore/upload.keystore`
(alias `upload`) и выполняет `jarsigner -verify` + `bundletool validate`. Пароль читается из
`keystore/rustore/upload-pass.txt` или `UPLOAD_PASS`; основной ключ APK не используется для подписи
AAB. Дополнительная приёмка: `bundletool build-apks --mode=universal` и проверка манифеста/подписи
полученного APK; технический universal APK подписывается debug key и **не предназначен для RuStore**.

В RuStore при первой настройке подписи загружаются `pepk_out.zip` и `uploadcert.pem`, затем для
каждой версии — свежий AAB. Закрытые ключи, pass-файлы и `pepk.jar` не загружать. В примечаниях
`docs/RELEASE-NOTES-X.Y.Z.md` обязателен раздел **«Кратко для RuStore»** с понятным пользователю
описанием изменений. Факт загрузки, прохождения модерации и публикации фиксировать отдельно по
результату в консоли, а не по наличию собранного AAB. Полный чек-лист — `docs/RELEASE.md`.

**Эмулятор на Windows** (с 2026-11-23): Android SDK в `C:\Users\x4k3r\devtools\android-sdk`
(cmdline-tools, platform-tools 37, emulator 37.3, platform 35, образ
`system-images;android-35;google_apis;x86_64`), AVD — `AnOOPlan35` (pixel_6, Android 15).
WHPX работает (ускорение есть, `-accel-check` зелёный). ВАЖНО: AVD создан с `hw.ramSize =
1536M` — с такой памятью lowmemorykiller убивает renderer WebView и приложение показывает
белый экран; в `~/.android/avd/AnOOPlan35.avd/config.ini` выставлено `hw.ramSize = 4096M`,

`adb install -r build/AnOOPlan-<версия>.apk`; `adb` — `devtools/android-sdk/platform-tools/adb.exe`.
Логи WebView: `adb logcat -d | grep chromium` (CONSOLE — ошибки JS).

**Баг 3.0.0, найденный эмулятором:** `NativeBridge.isTrustedOrigin()` вызывал
`webView.getUrl()` с потока JavaBridge → RuntimeException на Android 15, «Uncaught Error»
при инициализации и пустой экран. Исправлено: URL мосту передаёт `WebViewClient.onPageStarted`

Если keystore на машине нет (новая сессия/контейнер), подписанный APK локально не собрать: для проверки
собирается `UNSIGNED_APK=1 npm run build:apk` (версия/versionCode, отсутствие `INTERNET`, вес), а подпись
и сертификат проверяет `android-release.yml` из GitHub Secrets. Не генерировать новый ключ без решения
владельца: это ломает обновление поверх установленного приложения.

## CI и релиз

- `.github/workflows/ci.yml` — обязательный прогон на каждый push/PR: `npm ci`, `npm run lint`,
  `tsc --noEmit`, тесты с покрытием (`npm run coverage`, lcov), загрузка покрытия в Codacy при наличии
  секрета `CODACY_PROJECT_TOKEN`, сборка + бюджет бандла (`npm run size`), смоук, E2E.
  Это единственный автоматический workflow; держать job ≤130 с (2.5.0 — 123 с; 2.6.0 — 108 с;
2.6.1–2.6.2 — 105 с; очередь раннера в бюджет не входит и иногда добавляет ~30 с).
- `.github/workflows/android-apk.yml` — **вручную** (`workflow_dispatch`): неподписанный APK
  (`AnOOPlan-apk-unsigned`) для проверки установки. Ключ в раннере не создаётся.
- `.github/workflows/deploy.yml` — **авто по push** при изменениях приложения (`src/**`, `index.html`,
  `package.json`, lock, `vite.config.*`, сам workflow); `workflow_dispatch` сохранён для ручной публикации.
- `.github/workflows/android-release.yml` — по тегу `v*`: тесты, смоук, E2E, подписанный APK
  из GitHub Secrets, проверка SHA-256 сертификата, GitHub Release (описание берётся из аннотированного
  тега через GitHub API — checkout делает локальный тег облегчённым; есть fallback на локальную
  аннотацию и сообщение коммита), удаление keystore с раннера.

Порядок релиза:

1. Поднять версию: `version` и `androidVersionCode` в `package.json` (единственный источник),
   затем те же значения в `android/AndroidManifest.xml` — тест проверяет совпадение; `build-apk.sh`
   берёт версию из `package.json`.
2. Обновить `README.md` и этот файл, прогнать `npm test`, `npm run coverage`, `npm run size`,
   `npm run smoke`, `npm run test:ui`, `npm run build`.
3. Снять **1–3 скриншота изменений** (минимум один) на эмуляторе/в Chromium; сохранить в
   `build/release-screenshots/` (git не трогаем).
4. Закоммитить и запушить `main`; дождаться зелёного CI (`ci.yml`).
5. Поставить **аннотированный** тег `vX.Y.Z` с описанием изменений и запушить его — релиз соберёт
   workflow, а сообщение тега станет описанием GitHub Release (поэтому не пустой `Full Changelog`).
6. Приложить 1–3 скриншота к опубликованному Release (assets и/или описание) и проверить, что в
   GitHub Release есть APK и сертификат совпал с `ANDROID_CERT_SHA256`.
7. После релиза — обновить HANDOFF (состояние, ссылка на релиз) и, при необходимости, вручную
   опубликовать веб-версию (`deploy.yml`).

Локальная подпись: `KS_PASS=... bash scripts/build-apk.sh` или пароль из `keystore/pass.txt`.
Не коммитить `keystore/`, `build/`, `tools/`, `android/assets/`, `.env` и любые токены.

## Данные, хранение и диагностика

- Проекты: `localStorage` `cableplan:projects`; черновик — `cableplan:autosave`.
- PDF и фото: IndexedDB `cableplan`, хранилище `pdfs`; PDF — ключ без префикса, фото — `photo:<key>`.
- Пины: массив `project.pins` в JSON, фото пинов — те же `photo:<key>`, что у оборудования.
- Снимки: хранилище `snapshots`, ключ `<projectId>:<timestamp>`, максимум 20 на проект.
- Диагностика: `cableplan:diagnostics`, до 50 записей, экспорт в текстовый файл.
- Покрытие: `coverage/lcov.info` — артефакт `npm run coverage`, в git не входит (`coverage/` в `.gitignore`).
- GC запускается через 3 секунды после изменений и учитывает undo/redo и снимки. Поэтому старый блоб
  может оставаться, пока на него ссылается история; это защита undo, а не утечка. После перезапуска
  приложения история очищается, и сироты удаляются, если на них не ссылаются снимки.
- `schemaVersion: 2`: в v2 добавлены пины. Миграция `v1 → v2` в `src/migrations.ts`; проекты
  из будущей версии отклоняются. В 1.15.0 схема не менялась: поля `outerDiameterMm`/`crossSectionMm2`
  у кабеля и `trayWidthMm`/`trayHeightMm`/`trayAreaMm2` у трассы необязательны и нормализуются при
  загрузке (мусор → `undefined`, не 0; 0 и отрицательные сохраняются и ловятся валидацией).
  В 1.16.0 схема тоже не менялась: `Equipment.color` (необязательный `#rrggbb`) хранится в JSON
  оборудования и нормализуется при загрузке, как и остальные новые поля. В 1.17.0 добавлены
  `Project.catalog` (справочник цен), `Project.catalogDate` и `Project.estimate`; они необязательны,
  нормализуются при загрузке и входят в снапшоты/JSON-копию. В 1.18.0 расширен `Project.document`
  (титульный лист и `changeLog`) — тоже необязательные поля, нормализуемые при загрузке;
  `.anooplan` содержит те же данные, что резервная копия, плюс маркер формата. В 2.3–2.5 схема
  не менялась: `Project.dimensions` (размеры между оборудованием), `Route.subsystem`, поля
  `PriceItem.manufacturer/article/series/size` и `Segment.trayWidthMm/trayHeightMm/trayAreaMm2`
  (сегментные размеры КНС) необязательны и нормализуются при загрузке. Мусор в сегментных размерах
  (`abc`, boolean, массив) отбрасывается, числовые строки приводятся к числу, 0/отрицательные
  сохраняются и ловятся валидацией — так же, как у размеров трассы.
  Ревизии сущностей и облачная синхронизация — в планах; в текущей схеме их нет.

1. Клонировать репозиторий / открыть `/home/office/AnOOPlan`, `git checkout main && git pull`.
2. `npm ci && npm run lint && npm test && npm run smoke` — убедиться, что база зелёная (562/241);
   `npm run coverage` и `npm run size` — пороги (93/85/92 %, JS ≤600 КБ, CSS ≤60 КБ).
3. `bash scripts/fetch-tools.sh && bash scripts/build-apk.sh` — собрать APK 3.1.0 локально
   (на VPS keystore уже на месте; на Windows — по разделу «Сборка APK»); проверить
   версию/versionCode 51, сертификат и отсутствие `INTERNET`, вес ≤4 МБ, запуск на эмуляторе
   `AnOOPlan35` и `bash scripts/test-emulator-restore.sh` (E2E восстановления).
   Без keystore — `UNSIGNED_APK=1` или релиз по тегу.
4. Взять следующую итерацию: **3.2.0 «Полная смета»** — ждёт решений владельца
   (ROADMAP раздел 2: фитинги/крепления КНС, лист «Подписи», бренды демо).
   Дальше — 3.3.0 «Серверный режим». Остаток производительности: поля свойств объектов
   (не название проекта) по-прежнему пересчитывают производные на символ — при жалобах
   переводить на `derived: false` или локальное состояние.
5. Прочитать [ROADMAP.md](ROADMAP.md) и [ARCHITECTURE.md](../ARCHITECTURE.md) перед изменением модели.
