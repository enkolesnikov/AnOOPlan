# Контекст-хендофф: AnOOPlan

Документ для продолжения работы в новой сессии. Прочитайте его целиком перед первым действием.
Секретов здесь нет: ключи и токены передаются отдельно и в репозиторий не попадают.

## Что это за проект

**AnOOPlan** — Android-приложение (APK) для раскладки кабельных трасс по PDF-планам здания и расчёта
кабельного журнала. Выросло из веб-приложения [ooplan](https://github.com/enkolesnikov/ooplan) (CablePlan):
тот же движок расчёта, но интерфейс упакован в нативное приложение, которое работает офлайн, без сервера.

- Репозиторий: <https://github.com/enkolesnikov/AnOOPlan>
- Релизы с APK: <https://github.com/enkolesnikov/AnOOPlan/releases>
- Веб-версия (GitHub Pages): <https://enkolesnikov.github.io/AnOOPlan/>
- Текущая версия: **1.8.2**, versionCode 13, APK ~1,8 МБ, `com.anooplan.app`, minSdk 24, targetSdk 35

## Стек и устройство

| Слой | Где | Что внутри |
|---|---|---|
| Движок расчёта | `src/engine.ts` | длины, запасы, автопрокладка (Дейкстра), спецификации, проверки |
| Модель данных | `src/model.ts` | `Project` → этажи, оборудование, трассы, кабели, документ |
| Интерфейс | `src/App.tsx` | один компонент: план на canvas+SVG, свойства, журнал, ведомости |
| Выгрузка | `src/sheets.ts`, `src/export-xlsx.ts`, `src/export-pdf.ts` | общие листы, XLSX (SheetJS), PDF (pdf-lib + PT Sans) |
| План в PDF | `src/plan-svg.ts` + `capturePlan()` в App | SVG трасс → растр поверх подложки |
| Рендер больших листов | `src/render-plan.ts` | бюджет 12 Мпикс, рендер видимой области для A1/A0 |
| Оболочка Android | `android/java/com/anooplan/app/` | `MainActivity`, `AssetServer`, `NativeBridge`, `PdfPrinter` |
| Сборка APK | `scripts/build-apk.sh` + `scripts/fetch-tools.sh` | aapt + javac + d8 + zipalign + apksigner, **без Gradle** |
| Тесты | `tests/*.test.ts`, `scripts/smoke-dom.mjs` | 69 юнит-тестов + смоук интерфейса в happy-dom |

### Ключевые решения (не пересматривать без причины)

1. **WebView вместо Kotlin-переписывания.** Одна кодовая база для сайта и APK, 69 тестов, быстрые итерации.
   Kotlin оправдан только при ежедневном рисовании пером и листах A1+ — тогда начинать с порта `engine.ts` в KMP.
2. **Статика отдаётся по origin `https://appassets.local/`** через `AssetServer.shouldInterceptRequest`.
   На `file://` не работают IndexedDB и `crypto.randomUUID()`. Запросы `/api/*` получают 404 → приложение
   само включает режим «Браузер» (`staticMode`).
3. **Всё офлайн.** Разрешение `INTERNET` не запрашивается. Проекты — localStorage, PDF/фото/снимки — IndexedDB.
4. **Экспорт на клиенте.** XLSX и PDF собираются в телефоне (ленивые чанки), печать — `PrintManager`
   с PDF-паспасом в спулер без растеризации.
5. **Подпись.** `keystore/anooplan.jks` (в `.gitignore`), пароль в `keystore/README.txt`. Потеря = невозможность обновлений.

## Команды

```bash
npm ci                     # зависимости (Node 22.5+, проверено на 24)
npm test                   # 69 тестов
npm run smoke              # смоук интерфейса (happy-dom)
npm run build              # tsc --noEmit + vite build
npm run build:apk          # tools/android.jar + build-tools/35.0.0 + r8.jar → build/AnOOPlan-<версия>.apk
bash scripts/fetch-tools.sh # скачать platform-35, build-tools 35.0.0 и r8.jar
```

Сборка APK в CI: `.github/workflows/android-apk.yml` — использует предустановленный Android SDK раннера,
собирает артефакт `AnOOPlan-apk`, тесты и смоук идут до сборки. Деплой сайта — `deploy.yml` (GitHub Pages).

Релиз: поднять версию в `android/AndroidManifest.xml` и в `scripts/build-apk.sh` (`VERSION_NAME`, `VERSION_CODE`),
собрать APK, создать GitHub Release и приложить APK, затем `git push`.

## Известные проблемы и техдолг (P0 → P2)

**P0**
— закрыты все пять пунктов: фото-блобы, совместимость WebView, targetSdk 35, экран лицензий, pdfjs-dist.

**P0 (остаток, без фикса)**
- `npm audit`: `xlsx` 0.18.5 — фикса в npm нет; используется на запись и в тестах, на чтение не применяется.

**P1**
- План в PDF — только `floor.page`; для многостраничных этажей выгружать все страницы.
- Диагностика в приложении: версия, версия WebView, занятое место, экспорт лога ошибок.
- Доступность: `aria-label`, крупный шрифт, режим высокой контрастности; `textZoom(100)` игнорирует системный размер.
- Подмножество шрифта (npm `subset-font`) уменьшит APK с 1,7 до ~1,1 МБ.
- Память: 12 Мпикс ≈ 48 МБ на канву; для бюджетных телефонов разумнее 6–8 Мпикс с предупреждением.

**P2**
- Векторный план в PDF вместо растра 1600 px.
- Сравнение снимков версий (diff).
- Остались неиспользуемые стили `.export-menu`.

## Идеи следующих итераций

1. **Каталог и деньги**: справочник моделей оборудования и марок кабеля с ценами, смета по разделам,
   коммерческое предложение (PDF/XLSX).
2. **Обмен и печать**: `ACTION_SEND`, ассоциация `.anooplan`, титульный лист, штамп по ГОСТ 2.104,
   оглавление, лист регистрации изменений.
3. **Домен**: проверка заполнения лотка (сколько кабелей и % сечения), автопрокладка без начерченных трасс,
   пины-замечания с фото (punch list).
4. **Поле**: тёмная тема/высокий контраст, крупный шрифт, камера с коррекцией перспективы.

## Инфраструктура (VPS)

- VPS: `201.58.151.95`, Ubuntu 24.04 x86_64, 4 vCPU, 8 ГБ RAM, 60 ГБ, есть `/dev/kvm`.
- Node 24.19.0 в `/usr/local/lib/nodejs`, `dsh` — глобально.
- Веб-интерфейс DSH: `systemctl status dsh-web`, порт 3480, ссылка с токеном — `dsh-link`
  (токен меняется при каждом перезапуске, берётся из `journalctl -u dsh-web`).
- Ключ провайдера лежит в `/etc/dsh/env` (0600), юнит подключает его через `EnvironmentFile`.
- Для сборки на VPS: `git clone`, `npm ci`, `bash scripts/fetch-tools.sh`, `npm test`, `npm run smoke`,
  `bash scripts/build-apk.sh` (на x86_64 доступны официальные build-tools; можно перейти на Gradle).

## Правила для новой сессии

- Начинать с чтения этого файла и `README.md`, затем `npm ci && npm test && npm run smoke`.
- **Не коммитить**: `keystore/`, `tools/`, `build/`, `android/assets/`, ключи, токены, `.env`.
- Перед пушем: тесты + смоук зелёные, версия поднята, README обновлён.
- Релиз: собрать APK, создать GitHub Release с описанием изменений, приложить APK.
- Не менять политику устройства (DSHA) и не пытаться обойти блокировки доступа.
- Секреты (токен GitHub, ключ DeepSeek) приходят отдельным сообщением; в файлы их не писать.
