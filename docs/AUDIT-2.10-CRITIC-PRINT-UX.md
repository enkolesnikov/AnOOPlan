## Воспроизведения и ожидаемое поведение

### 1. P1 — количество 1000 рвётся на «100» + «0»
`buildJournalPdf(demo, fonts)` с `project.cables[0].quantity = 1000`, `pricePerMeter = 1234.56`.
Строка журнала (y=493) содержит `… 15,3 | 100 | 15 300 …`; на y=482.5 в той же колонке `Кол.`
печатается `0` (x=597). Для `quantity=20000` — `200` и `00`.
Причина: все ячейки проходят через `wrapText` (`export-pdf.ts:365`), а колонка «Кол.» имеет
ширину 26 (`:849`); при 7,6 pt и padding 4/4 в неё влезает 3 цифры.
Ожидаемо: числовые ячейки не переносятся (уместить `1000` в одну строку: шире колонка,
меньше кегль для чисел или неразрывная строка). Тот же механизм рвёт «Цена, ₽/м» при
цене `1 234 567,89` — `1 234` + `567,89` (проверено).

### 2. P1 — заголовок плана/фото без изображения (E-03)
Полный комплект (`include` по умолчанию) + один план: «План: Этаж 1» на листе 7, изображение
(1 XObject) — на листе 8. То же с двумя фото: заголовок «Фотографии оборудования» на листе 7,
оба изображения — на листе 8. В режиме `include: ['plans']` заголовок и план совпадают (лист 3).
Причина: `plans()` резервирует только `56 + noteLines*13 + 20` (`:514-515`), а высота картинки —
до 380, и `ensure(height+16)` (`:527`) срабатывает уже после заголовка; `photos()` делает
`ensure(imageHeight+captionHeight+12)` (`:479`) после `heading()`.
Ожидаемо: заголовок и изображение всегда на одном листе (резерв = фактическая высота картинки
или перенос обоих на новый лист). Заодно запись оглавления для плана указывает на лист 7, где
плана нет.

### 3. P1 — статус сметы на телефоне 49 px (28 px при 130 %)
360×800, «Учебный проект» → «Смета». `.document-title` — строка (`styles.css:307`), второй
flex-элемент `.estimate-status` (`:325`) сжимается до 49×241: badge «Смета рассчитана» — 49×94
(текст по слогам), «Дата прайса: 2026-10-01» — 49×60, «работы: 25 % …» — 49×75. При имитации
textZoom 130 % (кегль всех узлов ×1.3, коробки не меняются) ширина статуса — 28 px.
Ожидаемо: на ≤640 px `document-title` — колонка (или статус отдельной строкой во всю ширину),
badge в одну строку, переносы только по словам.

### 4. P1 — «Итого до НДС» = сумма с НДС
`project.estimate = { laborPercent: 25, vatRate: 20, vatIncluded: true }`:
estimate() = materials `115 134,7`, labor `28 783,675`, total `143 918,375`, vat `23 986,396`,
gross `143 918,375`. В PDF (`export-pdf.ts:762`) и UI (`estimate-screen.tsx:143`) строки:
«Итого до НДС 143 918,375», «НДС 20 % (в т.ч.) 23 986,396», «Итого с НДС 143 918,375».
«До НДС» не может равняться «с НДС»; net = `119 931,979`.
Ожидаемо: либо `total − vat` в строке «Итого до НДС», либо переименовать строку
(«Итого по смете»), не выдавая сумму с налогом за сумму до налога. В PDF у НДС «сверху»
нет пометки «(сверху)» (в UI есть) — привести к одному виду.

### 5. P2 — пустая страница оглавления
`buildJournalPdf(demo, fonts, { plans: 3, photos: 1 })` → 12 листов; лист 3 содержит только
штамп/колонтитул (0 элементов контента), хотя все 15 записей уместились на листе 2.
Причина: `expectedEntries` безусловно прибавляет `+1` (`:1060`, задумано под предупреждения),
а предупреждений нет; `ceil(16/15)=2` листа оглавления, второй не нужен.
Ожидаемо: резервировать столько листов, сколько фактических записей (учитывать наличие
раздела предупреждений), либо не печатать пустой лист.

### 6. P2 — «— ₽» в спецификации КНС
Проект без справочника цен (`delete project.catalog`): на листе КНС
`Итого по типам: Лоток — 55 м, — ₽; Стояк — 4 м, — ₽. Всего КНС: 59 м, — ₽. …`
(`export-pdf.ts:922`, `:924`). В UI валюты после прочерка нет (`moneyText` → `—`).
Ожидаемо: «стоимость не рассчитана» / «—» без «₽»; не приписывать валюту к неизвестному числу.

### 7. P2 — масштаб 110 % ломает заголовки
`buildJournalPdf(demo, fonts, { scale: 1.1 })`: заголовки `Геометри…`, `Запас тр…`,
`Запас ка…`, `К…`, `Стоимость…`. `К…` — это «Кол.». При 90/100 % таких нет (кроме
`Запас каб…` при 100 %). Причина: `fitText` заголовка (`:313-322`) при ширине колонки
«Кол.» 26 (`:849`) и кегле 8,14.
Ожидаемо: поддерживаемый масштаб не должен превращать заголовок в одну букву — расширить
узкие колонки или уменьшать кегль только заголовка.

### 8. P2 — титул: длинные реквизиты без переноса
`document.organization` = 149 симв. → одна строка, x=34, right=846,3 (край листа 842,
рамка 824): текст обрезан краем. `document.title` 200 симв. → «Дата: 2026-10-01» (y=103)
пересекается с «Екатеринбург · 2026» (y=95); при 400 симв. дата уходит ниже рамки (y=13).
Ожидаемо: организация/название проекта переносятся или усекаются с «…»; позиции даты и
города считаются от фактической высоты заголовка с минимальным зазором.

### 9. P2 — неверное округление молчит в UI
`project.estimate.rounding = 3`: `estimate()` даёт warning «Смета: неверное правило округления»
и `complete: true`; `EstimateScreen` рендерит предупреждения только при `!result.complete`
(`estimate-screen.tsx:367`), select показывает «Без округления». В PDF предупреждение есть.
Ожидаемо: показывать предупреждения при любом непустом списке или помечать смету неполной;
нельзя молча терять сохранённое правило округления.

### 10. P2 — процент работ в режиме «по видам» принимается и игнорируется
В режиме «по видам» поле «Работы, %» активно; ввод 25 оставляет итог «Работы (по видам) 2 000 ₽»,
предупреждений 0, подсказка только в `title` у label (`:66`), на телефоне hover нет.
Ожидаемо: disabled-поле с видимой подписью «в режиме по видам не применяется» либо warning.

### 11. P2 — невалидное число не сообщает об ошибке
В «НДС, %» ввод `-5` (поле в фокусе, затем тап мимо): после blur поле молча пустеет,
статус — «без НДС», предупреждений 0; `abc` — так же. `NumberField` коммитит только
finite-числа, а невалидное/отрицательное отбрасывает в `nonNegativeOrNull` без обратной связи
(`number-field.tsx:24-32`).
Ожидаемо: явная ошибка поля или сообщение о сбросе; пользователь не должен гадать,
принято ли введённое значение.

### 12. P2 — примечание кабеля не попадает в PDF
`cable.note` (и `purpose`) не входят в колонки журнала PDF (`export-pdf.ts:710-730`), хотя есть
в XLSX/CSV. 3000+ симв. примечания не появляются в тексте PDF вообще (проверено).
Ожидаемо: либо печатать примечание (тогда проверять E-04 на нём), либо зафиксировать в
документации, что PDF-журнал — сокращённая форма.

### 13. P2 — продолжение длинной строки без номера
Ячейка 4734 симв. (наименование кабеля) → 4 листа-продолжения: `(продолж.)` есть на каждом,
шапка повторяется, весь текст на месте (45/45 токенов), но «№» и все числовые колонки на
продолжениях пусты: строку нельзя сопоставить с кабелем. Маркер стоит в колонке «№»,
а не в длинной ячейке (`:404-410`).
Ожидаемо: повторять номер строки/кабеля на каждом листе-продолжении (или печатать
«(продолж.) Л1» в колонке «№»).

### 14. P2 — лимит 12 листов не объяснён на бумаге
`planSheetsForPdf` при 20-страничном PDF даёт warning «показаны первые 12 страниц из 20»
(`plan-pages.ts:101-106`), но `buildJournalPdf` его не получает: в PDF только изображения и
заголовки. Проверено: PDF из 12 планов не содержит «показаны первые 12». В приложении
предупреждение показывается тостом (`use-export.ts:40`, `:101`).
Ожидаемо: вынести предупреждение на первый лист плана (как `sheet.note`) или в раздел
предупреждений PDF.

### 15. P2 — FAB перекрывают поля сметы
360×800, смета, scrollY=0: `.history-fab` (46×100 @x300,y538) накрывает select «Округление»
(x174..334, y582..622) — под кнопкой ↷ стрелка select; `.props-fab` (54×54 @x292,y650)
накрывает поле «Примечание к смете» (x10..350, y656..696). Проверено пересечением
`getBoundingClientRect`.
Ожидаемо: отступ/подъём FAB на документных экранах или скрытие ⚙ там, где нет выбранного
объекта; поля должны быть полностью доступны для касания.

### 16. P2 — длинное имя этажа в заголовке плана
Имя 185 симв. → «План: …» right=846,6 (предел 808) на листе плана и right=842,1 в оглавлении,
где наезжает на номер страницы (x≈802). `heading()` и `drawContents()` рисуют title без
`fitText`/переноса (`:261`, `:557`).
Ожидаемо: усечение с «…» или перенос; в оглавлении номер страницы всегда отделён.

### 17. P2 — нет визуальных эталонов сметы
`tests/visual/visual.spec.ts` содержит 4 снимка (план, сечение, тёмный план, схема трасс).
Экран сметы, мобильная ширина 360, тёмная тема сметы и font_scale 1.3 не покрыты, поэтому
P1 № 3 проходит все проверки. Ожидаемо: эталоны `estimate-mobile`, `estimate-dark`,
`estimate-font130`.

### 18. P2 — 30×30 кнопки удаления
`.catalog-table .catalog-remove button` и `.works-table .works-remove button` — 30×30
(`styles.css:369`, `:382`) при общей норме мобильных целей 40/44 px (`:571`, `:584`).
Ожидаемо: ≥40 (лучше 44) px по каждой стороне.

- **Тёмная тема:** контраст `--muted` на `#13252f` — 8,23:1 (`estimate-section-total span`,
  `help`, legend), на `#1a2f3a` — 7,26:1 (`estimate-totals span`); предупреждения и badge
  читаются (скриншоты 360×800).
- **Крупный шрифт:** имитация textZoom 130 % (кегль ×1.3) — горизонтального скролла нет,
  видимые поля не обрезаны по вертикали; единственный клип — скрытый `.sr-only`. Но статус
  при этом сжимается до 28 px (см. P1 № 3).
- **Пустой/неполный проект:** «Смета неполная», «не задан процент работ», «не рассчитано»,
  «0 ₽» только для действительно нулевых материалов; `undefined`/`NaN` нет.

## Ограничения метода

- PDF не растеризовался (нет canvas/poppler): наложения, отступы и «читаемость» проверены по
  координатам текста и размерам страниц, а не глазами.
- Font scale 1,3 имитировался увеличением кегля всех узлов без изменения коробок (приближение
  `WebSettings.setTextZoom`), не реальным Android WebView.
