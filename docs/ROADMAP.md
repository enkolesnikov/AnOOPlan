# План развития AnOOPlan — Android-first

Роадмап от **2026-10-27**, после релиза **2.6.2 «Техдолг»**. Фокус следующих версий —
**удобство ежедневной работы и полезные функции**: меньше действий на типовую операцию, быстрее от
плана до готового комплекта документов. Облако не возвращаем (дальняя перспектива, отдельное решение
владельца), фитинги/крепления не считаем — важны только углы коробов.

## 0. Принципы

1. **Меньше действий.** Поиск, мультивыбор, дублирование, шаблоны и горячие клавиши важнее экзотики.
2. **Дешёвые победы первыми.** Сначала UX-мелочи с высоким эффектом (S), затем тяжёлые сценарии (M/L).
3. **Поле.** Телефон одной рукой, крупные цели, офлайн; ничего не теряется при сворачивании.
4. **Офлайн-контракт неизменен.** Ни `INTERNET`, ни сетевых вызовов, ни облачных SDK.
5. **Бюджеты не размываются.** APK ≤1,6 МБ, JS ≤460 КБ, CSS ≤40 КБ, CI ≤130 с, 0 high — в каждом релизе.
6. **Каждый релиз — самостоятельная ценность** и обратно совместимый проект `.anooplan`.

### 2.7.0 — «Мастера и шаблоны» (M)

Цель: новый проект и типовой узел создаются за минуты, а не с нуля.

- **Онбординг:** 5 шагов на демо-проекте (PDF → калибровка → оборудование → трасса → документы),
  повторный запуск из меню, без сетевых ассетов.
- **Шаблоны проектов:** «Офис», «Склад», «КЖ площадка», «Пустой»; «Сохранить текущий как шаблон»
  (локально, в IndexedDB) и удаление шаблонов.
- **Комплекты оборудования:** вставка набора (например, «камера + шкаф + кабель») одним действием,
  относительное расположение сохраняется.
- **Импорт справочника цен из XLSX/CSV:** маппинг колонок, предпросмотр первых строк, отчёт об ошибках,
  обновление существующих позиций; `series`/`size` редактируются в UI.
- **Массовые цены:** наценка/скидка на раздел, «обновить цены по дате», история изменения цен.
- **Проекты:** список недавних на старте, дублирование проекта, «Открыть последний».

**Готово, если:** импорт 1000 строк <2 с с отчётом; шаблон создаёт готовый проект с этажами и
оборудованием; тесты парсера и маппинга; `.anooplan` со шаблоном не ломает старые версии.

### 2.8.0 — «Чертёж без трения» (M–L)

Цель: правки плана перестают быть самой долгой частью работы.

- **Трассы:** вставка/удаление вершины на сегменте, разделение и объединение трасс, реверс направления,
  перенос вершины с согласованием соседей (подсказка о разрыве).
- **Привязки:** к оборудованию и сетке, индикатор ортогональности, подсветка угла/стыка, «прилипание»
  при перетаскивании на зуме.
- **Размеры:** цепные размеры, размер сегмента трассы на плане, **межэтажные размеры** (P1 из аудита).
- **Автосохранение:** видимый индикатор «сохранено/есть изменения», восстановление после сбоя
  с выбором «восстановить/начать заново».
- **Векторный план в PDF:** встраивать исходную страницу PDF как форму (`pdf-lib.embedPage`) вместо
  растра 1600 px — резкость на A1 и меньше вес файла; растр остаётся fallback.

**Готово, если:** план A1 в PDF читаем при 100 % без «мыла»; файл не вырос; правка трассы на 20 вершин
без рывков; тесты геометрии новых операций; старые проекты открываются без миграции.

### 2.9.0 — «Документы и смета» (M)

Цель: комплект документов выходит из приложения без доработки в Excel.

- **Печатные формы:** полный штамп ГОСТ 2.104, оглавление, «Лист N из M», выбор формата/масштаба,
  единый стиль таблиц.
- **Смета:** работы по видам, НДС (ставка и включение), разные единицы, правила округления, итоги
  по разделам; печать коммерческого предложения.
- **Спецификация КНС:** цена/артикул **по сечению** (фикс известного ограничения), группировка по
  подсистемам, итоги по типам.
- **XLSX:** форматирование (ширины, шапки, итоговые строки), отдельные листы журнала/КНС/сметы.

**Готово, если:** сумма сметы совпадает с ручным эталоном в тестах (НДС/округление/работы);
PDF-эталон проходит визуальную проверку; смешанные сечения дают разные артикулы; бандл не растёт
больше чем на ~10 КБ (формы печати уже ленивые).

### 3.0.0 — «Поле и надёжность» (L)

Цель: приложение не подводит на объекте и на больших проектах.

- **Данные:** напоминание о резервной копии, авто-экспорт `.anooplan` раз в N сохранений, проверка квоты

- **Диагностика:** экран «О программе» с версией WebView, занятым местом, размером проекта, экспортом
  диагностического отчёта (без сети).
- **Производительность:** 1000+ объектов и 100+ трасс без фризов панорамирования, профиль рендера,

- **Тех.долг:** декомпозиция `engine.ts`, `export-pdf.ts`, `properties-panel.tsx`, `MainActivity`;

- **Геометки пинов (опционально):** офлайн-GPS без `INTERNET` — только по отдельному решению владельца.

**Готово, если:** проект на 1000 объектов открывается и панорамируется без фризов; APK ≤1,6 МБ,

## 6. Что не делаем

- **Фитинги, тройники, крепления** — по решению владельца; считаем только углы коробов.
- **Облако и real-time** — только отдельным решением владельца, не «между делом».
- **Kotlin-переписывание** — пока WebView справляется; пересматривать при ежедневном стилусе/A1+.
- **DWG/IFC/десктопная САПР** — вне мобильного сценария.
- **Google Play, подписки, маркетплейс** — не влияют на основной сценарий.
- **Тяжёлые ML/OCR и любые сетевые SDK** — конфликт с бюджетом APK и офлайн-контрактом.
- **Автодеплой Pages** — только вручную.

## 10. Риски

- **Расползание UX-скоупа:** каждая «мелочь» тянет состояние и тесты. Держим релиз по теме, лишнее —
  в следующий.
- **Производительность:** поиск, мультивыбор и виртуализация добавляют подписки на состояние — следить
  за числом ререндеров и размером бандла.
- **Бюджет APK:** векторный план и печатные формы не должны тянуть библиотеки; используем `pdf-lib`.
- **Совместимость проектов:** шаблоны и новые поля — только необязательные, миграция как в 2.5.0.
- **Тип по подстроке:** свой тип вроде «Лоток перфорированный» распознаётся как лоток — это ожидаемо;
  экзотические названия получают нейтральный цвет, пока пользователь не задаст свой.
- **Круглые КНС:** диаметр занимает поле `trayWidthMm` — при импорте старых проектов с шириной лотка
  и типом «Труба» площадь может отличаться; в интерфейсе подписи различаются.
- **Углы:** считаются как изменения направления между соседними сегментами; для коробов это количество
  углов, а не фитингов.
- **Размеры:** сейчас только один этаж и плоское расстояние; межэтажные — в 2.8.0.
- **Внешние линтеры:** CodeFactor A, Codacy B; после добавления токена покрытие появится в отчёте,
  остальные сложные методы — в 3.0.0.
- **Сегментные размеры:** незаданные поля наследуются от трассы поле в поле, а не «сечением целиком»;
  углы коробов относятся к основному сечению, чтобы не задваиваться, — это осознанно.
- **textZoom:** диапазон 85–160 % — компромисс; вне него раскладка на телефоне разваливается.
- **Память рендера:** 8 Мпикс ≈32 МБ RGBA; при сильном увеличении возможна «мягкая» картинка —
  приоритет у стабильности WebView.
- **Страница этажа и PDF:** если `floor.page` вне диапазона, оверлей не наносится — на листе печатается
  note, но лучше проверять «Страницу» при замене PDF.
- **Сабсет шрифтов** не содержит редких глифов (см. HANDOFF); базовые кириллица/латиница гарантированы.
- **XLSX-зависимость** — tarball с `cdn.sheetjs.com`: `npm ci` требует доступ к этому хосту.
- **Офлайн-контракт:** любая новая зависимость проверяется на сетевые вызовы и разрешения.
