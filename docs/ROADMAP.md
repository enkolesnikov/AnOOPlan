# План развития AnOOPlan

План на ближайшие итерации. Базовая версия — **1.11.0** (89 тестов, E2E с реальным PDF, миграции,
подписанный release-workflow). Оценки — для одного разработчика, календарные, без согласований;
это ориентиры, а не обещания.

Правила итерации: одна цель, тесты, смоук, E2E (где применимо), APK, GitHub Release, обновление
`README.md` и `HANDOFF.md`. Версия — по SemVer: техническая итерация может быть patch/minor,
крупная продуктовая — minor, облако — major.

## Итерация 1 — 1.12.0: разобрать `App.tsx` и ускорить CI

**Цель:** уменьшить стоимость каждой следующей фичи. Поведение не меняется.

- Вынести из `App.tsx`:
  - `useProjectSession` — загрузка/сохранение, автосохранение, снимки, GC;
  - `useHistory` — undo/redo;
  - `usePlanViewport` — зум/пан/жесты;
  - `usePdfBackground` — эффект рендера PDF и кэш Canvas.
- Не переписывать UI и не менять CSS; каждый шаг — отдельный коммит.
- CI: кэшировать браузеры Playwright по версии пакета, вынести E2E в отдельный job или закэшировать
  зависимости; цель — обычный CI до 6 минут.
- Доступность: добавить текстовый список объектов как альтернативу canvas для скринридера
  (сворачиваемый, без изменения визуального интерфейса).

**Готово, когда:** `App.tsx` < 950 строк, все 89 тестов и E2E зелёные, CI заметно быстрее,
ручной сценарий «загрузить PDF → оборудование → экспорт» не изменился.

**Риск:** эффект PDF завязан на canvas/refs; выносить его последним и под E2E.

## Итерация 2 — 1.13.0: многостраничный план в PDF

**Цель:** этаж с многостраничным PDF выгружается полностью, а не одной страницей.

- `capturePlan` → `capturePlanPages`: все страницы PDF этажа.
- Оверлей трасс/оборудования — только на откалиброванной `floor.page`; остальные страницы — чистые
  листы с подписью «План: этаж, лист N».
- Прогресс выгрузки и защита от гигантских файлов: лимит страниц на этаж (например, 12) с понятным
  предупреждением, последовательный рендер без параллельного хранения всех PNG.
- Тесты: unit на выбор страниц/заголовки, E2E на двухстраничный PDF, проверка числа листов.

**Готово, когда:** 2–3-страничный PDF даёт столько же листов «План», оверлей только на выбранной,
журнал не падает по памяти на 12 страницах.

## Итерация 3 — 1.14.0: схема v2 и пины-замечания

**Цель:** первый полевой сценарий и подготовка данных к облаку.

- `schemaVersion: 2`; миграция v1 → v2, `project.revision`.
- Новая сущность `Pin`: этаж, x/y, комментарий, статус (открыто/закрыто), фото, автор/дата.
- UI: инструмент «Замечание», список с фильтром, переход к пину, фото.
- PDF: отдельный лист «Замечания» с планом/координатами и фото; XLSX-лист.
- JSON-копия и снимки включают пины.
- Тесты: миграция, CRUD пинов, PDF/XLSX, E2E.

**Готово, когда:** старый проект открывается без потерь, пин с фото попадает в PDF и переживает
сохранение/восстановление.

## Итерация 4 — 1.15.0: заполнение лотка

**Цель:** ответить на вопрос «влезет ли кабель в лоток».

- В кабеле — внешний диаметр или площадь сечения (по марке/вручную).
- В трассе/сегменте — размеры лотка (ширина/высота) или площадь.
- Расчёт заполнения % по сегменту, предупреждения при превышении порога (например, 40/50%),
  суммарный % в ведомости и PDF.
- Тесты движка: пустой лоток, переполнение, разные диаметры, неизвестные данные → «неполный расчёт».

**Готово, когда:** на демо-проекте видно заполнение по каждому сегменту, в PDF есть колонка/раздел,
неизвестные размеры не подменяются нулём.

## Итерация 5 — 1.16.0: каталог, цены и смета

**Цель:** превратить журнал в коммерческое предложение.

- Справочник моделей оборудования и марок кабеля с ценами; применение к проекту.
- Смета по разделам (оборудование, кабель, лоток, работы), итог.
- PDF/XLSX «Смета» и «Коммерческое предложение»; импорт/экспорт справочника.
- Версионирование прайса/дата актуальности.
- Тесты расчёта, PDF/XLSX, обновление снимков.

**Готово, когда:** проект с ценами даёт смету без ручных пересчётов; смена цены в справочнике
не ломает старые снимки.

## Итерация 6 — 1.17.0: печать и обмен

**Цель:** документы можно отдать заказчику без ручной сборки.

- Титульный лист, штамп по ГОСТ 2.104, оглавление, лист регистрации изменений.
- Печать выбранных разделов, а не только журнала.
- `ACTION_SEND` для PDF/XLSX, ассоциация `.anooplan`, открытие проекта из файла.
- Тесты форм, E2E печати/шаринга (где возможно).

## Итерация 7 — 2.0.0: облако без real-time

**Цель:** проекты не теряются и доступны с другого устройства.

- Аккаунты, PostgreSQL, объектное хранилище PDF/фото, синхронизация проекта и снимков.
- Read-only ссылка на проект, восстановление на втором устройстве.
- Оптимистичные блокировки: один редактор на проект, ревизии; без одновременного редактирования.
- Офлайн остаётся полноценным: локальная работа + очередь синхронизации.
- Безопасность: TLS, шифрование, ограничение доступа, аудит, резервные копии.
- Тесты API/синхронизации/восстановления; нагрузочный мини-тест.

**Готово, когда:** проект с PDF и фото создаётся на телефоне, восстанавливается на другом устройстве,
ссылка открывается только на чтение, офлайн-режим не деградировал.

  а не комментарии/согласование.

## Постоянные направления

- **Безопасность:** обновления зависимостей, `xlsx` (high без фикса), проверка подписи, резервные
  копии ключа.
- **Производительность:** память рендера 12 Мпикс, подмножество PT Sans (−0,6 МБ), векторный план
  вместо растра 1600 px.
- **Доступность:** системный размер шрифта (`textZoom`), canvas для скринридера, тёмная тема
  и высокий контраст.
- **Документация:** `HANDOFF.md` после каждой итерации, `RELEASE`-заметки, обновление README.

## Что не делаем сейчас

- **Kotlin-переписывание** — только при ежедневном стилусе/A1+ или если WebView начнёт блокировать
  развитие; промежуточный вариант — нативная растеризация PDF.
- **Real-time до облака** — сначала аккаунты, бэкап и комментарии.
- **Новые DSH-плагины** — текущий набор закрывает процесс; Git/память/браузер-плагины не нужны.
