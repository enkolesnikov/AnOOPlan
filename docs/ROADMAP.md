# План развития AnOOPlan — Android-first

Роадмап от **2026-11-19**, после аудита 2.9.0-дев. Версия в `package.json` остаётся **2.8.5**:
исправления уже в `main`, но релиз 2.9.0 не выпускался. Фокус — сначала надёжность данных и
корректность документов, затем удобство ежедневной работы.

## 0. Принципы

1. **Ничего не теряется.** Любое действие с данными либо завершается успешно, либо остаётся
   отменяемым; физическая очистка — только общий GC.
2. **Неизвестное ≠ 0.** Нет цены/высоты/масштаба — `null`, пометка «неполный», а не правдоподобное число.
3. **Меньше действий.** Поиск, мультивыбор, дублирование, шаблоны и горячие клавиши важнее экзотики.
4. **Поле.** Телефон одной рукой, крупные цели, офлайн; ничего не теряется при сворачивании.
5. **Офлайн-контракт неизменен.** Ни `INTERNET`, ни сетевых вызовов, ни облачных SDK.
6. **Бюджеты управляемые.** APK ≤4 МБ, JS ≤600 КБ, CSS ≤60 КБ, CI ≤130 с, 0 high. Повышаем только
   с записью причины и метрик.
7. **Каждый релиз — самостоятельная ценность** и обратно совместимый `.anooplan`.

### Что закрыто в 2.9.0-дев

- **Данные:** удаление этажа не стирает фото в обход GC; GC учитывает черновик другой вкладки;
  восстановление снимка сохраняется; удалённый проект не воскресает; повреждённый список проектов
  не затирается; миграция 1→2 сохраняет замечания.
- **Расчёты:** вставка вершины не удваивает фиксированный запас; разнотипные трассы не объединяются;
  разворот трассы не ломает кабель на стыке; межэтажный размер не подставляет 0; спецификация
  разделяет разные типы одного вида; удаление вершины не создаёт диагональ/неверный стояк.
- **Документы:** оглавление PDF на нескольких листах; примечание не разрывает лист плана;
  CSV с десятичной запятой; растр в бюджете памяти; `.anooplan` в окне восстановления.
- **Безопасность:** LAN-токен из браузера (cookie), auth до разбора JSON, restore проверяет
  SHA-256 и не теряет фото, dev-сервер на loopback.
- **Тесты:** +22 юнит-теста, тесты межвкладочного GC, серверного restore и переноса оглавления.

### 2.9.0 — «Документы и смета» (следующий релиз)

Цель: комплект документов выходит из приложения без доработки в Excel, а данные не меняются молча.

- **Печатные формы:** полный штамп ГОСТ 2.104, «Лист N из M», выбор формата/масштаба, единый стиль
  таблиц; продолжение длинных ячеек (E-04).
- **Смета:** работы по видам, НДС (ставка и включение), разные единицы, правила округления, итоги
  по разделам; печать коммерческого предложения.
- **Спецификация КНС:** цена/артикул **по сечению** (C-07), группировка по подсистемам, итоги по типам.
- **XLSX:** ширины колонок, закрепление шапки, автофильтр, отдельные листы журнала/КНС/сметы (E-09).
- **Планы:** не печатать общий PDF этажа повторно на каждом этаже (E-06); учитывать этаж только с пинами.
- **Проверки:** сумма сметы совпадает с ручным эталоном; PDF-эталон проходит визуальную проверку;
  смешанные сечения дают разные артикулы; бандл не растёт больше чем на ~10 КБ.

**Готово, если:** все находки high из AUDIT-2.9 закрыты или явно отложены с причиной; 0 high в
`npm audit`; APK ≤4 МБ; CI ≤130 с; 319+ тестов и 8+ E2E зелёные.

### 2.9.1 — «Точность и скорость» (S–M)

- **Углы:** единый обход сегментов по типу КНС, включая межэтажные стыки и разрезы (C-04).
- **Цены:** сопоставление `PriceItem.size` с сечением, отдельные строки сметы по сечениям (C-07).
- **Подбор сечения:** `null` при неполных данных, фильтр по сегментам (C-10).
- **Миграции:** не подменять `quantity=0`/`NaN` правдоподобными числами (C-09).
- **Скорость:** один `segmentIndex` на проект, `totals` из `cableCalcs`, индекс segment↔cable в
  `trayFill`; rAF-троттлинг drag; склейка безымянных `mutate` (P-01…P-03).
- **Экспорт:** `.anooplan` с `idb:`-id на сервере (E-12), лист предупреждений с `domainWarnings`
  (E-10), пустое имя проекта (E-11).
- **Тесты:** прямые тесты `useSnapshots`/`useProjectIo`, сценарий «удалить → undo → Blob жив».
- **Критерий:** ввод и drag на 2000 сегментах ≤16 мс/кадр; покрытие UI-хуков растёт; метрики
  сметы/углов совпадают с эталоном.

### 3.0.0 — «Поле и надёжность» (L)

- **Данные:** список проектов из одной localStorage-записи в IndexedDB, `navigator.storage.persist()`,
  индикатор квоты, авто-экспорт `.anooplan` раз в N сохранений.
- **Производительность:** culling плана по видимой области, виртуализация списков, 1000+ объектов
  и 100+ трасс без фризов; кэш тайлов подложки.
- **Полевой режим:** крупные цели, нижняя панель из 3–4 действий, быстрый пин с фото, вибро-подтверждение,
  фиксация ориентации, тёмная тема для улицы.
- **Диагностика:** экран «О программе» с версией WebView, занятым местом, размером проекта и
  экспортом отчёта без сети.
- **Тех.долг:** декомпозиция `export-pdf.ts`, `properties-panel.tsx`, `MainActivity`; Codacy-покрытие
  после токена.
- **Готово, если:** проект на 1000 объектов открывается и панорамируется без фризов; APK ≤4 МБ;
  CI ≤130 с; сценарий «сбой → восстановление» проверен на эмуляторе.

## 5. Что не делаем

- **Фитинги, тройники, крепления** — по решению владельца; считаем только углы коробов.
- **Облако и real-time** — только отдельным решением владельца.
- **Kotlin-переписывание** — пока WebView справляется; пересматривать при ежедневном стилусе/A1+.
- **DWG/IFC/десктопная САПР** — вне мобильного сценария.
- **Google Play, подписки, маркетплейс** — не влияют на основной сценарий.
- **Тяжёлые ML/OCR и сетевые SDK** — конфликт с бюджетом APK и офлайн-контрактом.

## 8. Риски

- **Расползание UX-скоупа:** каждая «мелочь» тянет состояние и тесты. Держим релиз по теме.
- **Производительность:** поиск и мультивыбор добавляют подписки на состояние; следить за числом
  ререндеров и размером бандла.
- **Бюджет APK:** печатные формы и векторный PDF не должны тянуть библиотеки; используем `pdf-lib`.
- **Совместимость проектов:** новые поля — только необязательные, миграция как в 2.5.0.
- **Тип по подстроке:** свой тип вроде «Лоток перфорированный» распознаётся как лоток — это ожидаемо;
  экзотические названия получают нейтральный цвет, пока пользователь не задаст свой.
- **Круглые КНС:** диаметр занимает поле `trayWidthMm`; при импорте старых проектов с шириной лотка
  и типом «Труба» площадь может отличаться; в интерфейсе подписи различаются.
- **Углы:** считаются как изменения направления между соседними сегментами; для коробов это количество
  углов, а не фитингов.
- **Внешние линтеры:** CodeFactor A, Codacy B; покрытие в Codacy появится после токена владельца.
- **textZoom:** диапазон 85–160 % — компромисс; вне него раскладка на телефоне разваливается.
- **Память рендера:** 8 Мпикс ≈32 МБ RGBA; при сильном увеличении возможна «мягкая» картинка —
  приоритет у стабильности WebView.
- **XLSX-зависимость:** tarball с `cdn.sheetjs.com`; `npm ci` требует доступ к этому хосту.
- **Supply chain:** не все инструменты закреплены по SHA; release-гейт дополнить в 2.9.1.
- **Офлайн-контракт:** любая новая зависимость проверяется на сетевые вызовы и разрешения.
