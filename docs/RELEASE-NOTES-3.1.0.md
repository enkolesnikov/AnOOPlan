# AnOOPlan 3.1.0 — «Оболочка и приёмка»

**Дата:** 2026-11-24 · **versionCode:** 51 · **minSdk 24 / targetSdk 35** · без `INTERNET`

**APK:** `AnOOPlan-3.1.0.apk` · сертификат не менялся — обновление ставится поверх 3.0.1.

## Кратко для RuStore

В AnOOPlan 3.1.0:

- **Приложение стало надёжнее при сбоях.** Если система выгрузила приложение на несохранённом
  проекте, при следующем запуске черновик восстанавливается автоматически — этот сценарий теперь
  проверяется автоматически на эмуляторе перед каждым выпуском.
- **В диагностике видно восстановление черновика.** На экране «О программе» фиксируется факт
  восстановления — проще понять, что происходило с приложением в поле.
- **Быстрее ввод на больших проектах.** Переименование проекта больше не запускает
  фоновые пересчёты на каждую букву — на планах из тысяч сегментов ввод стал заметно легче.
- Внутренняя переработка оболочки: нативная часть разобрана на модули, что снижает риск
  ошибок в следующих версиях. Для пользователя поведение не изменилось.

## Технические детали

- **Декомпозиция `MainActivity.java`** (651 → 163 строки): настройки окна и WebView —
  `WebViewConfigurator`, масштаб шрифта — `TextZoom`, выбор файлов и JS-диалоги —
  `JsDialogClient`, открытие `.anooplan` из системы — `SharedProjectReceiver`, «Назад» и выход
  с сохранением — `ExitController`, печать — `PrintJobs`. Поведение и контракт моста не менялись;
  инварианты проверяют те же стражи (`webview-security`, `android-config`, `release-config`),
  перепривязанные к новым файлам, плюс новый структурный тест «MainActivity ≤200 строк».
- **E2E «сбой → восстановление»** (`scripts/test-emulator-restore.sh`): чистая установка →
  правка проекта → `force-stop` (имитация сбоя) → повторный запуск; восстановление черновика
  проверяется по записи `autosave-restore` в полевой диагностике (adb root, leveldb) —
  uiautomator не видит содержимое WebView.
- **Полевая диагностика:** восстановление черновика из автосейва записывается в журнал
  диагностики (виден на экране «О программе»).
- **S-11 закрыт:** еженедельный Gitleaks по расписанию сканирует всю историю git
  (`fetch-depth: 0`); первый полный прогон 2026-11-23 — 0 находок. Запись —
  в [REPORT-SECURITY.md](REPORT-SECURITY.md).
- **Ввод на больших проектах ускорен.** Правка названия проекта раньше запускала полный
  пересчёт проверок и кабелей на каждый символ (~100–200 мс на символ на проекте
  2000 сегментов). Теперь тяжёлые производные считаются по редакции данных (`dataRev`)
  и правки метаданных их не трогают: JS на символ ≤5 мс, медиана кадра 16,7 мс.
  Замер — `tests/perf/plan-2000.spec.ts` (гейт по медиане; механизм сторожит
  `tests/history-derived.test.ts`), профилировщик — `scripts/profile-typing.mjs`.
