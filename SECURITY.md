# Безопасность AnOOPlan

AnOOPlan — офлайн-приложение: в APK нет разрешения `INTERNET`, данные проектов остаются на
устройстве. Но веб-сборка публикуется на GitHub Pages, а `npm start` поднимает LAN-сервер, поэтому
сообщения о проблемах безопасности мы разбираем как обычные баги — с приоритетом.

## Как сообщить об уязвимости

Предпочтительный способ — **приватный отчёт через GitHub Security Advisories**:

<https://github.com/enkolesnikov/AnOOPlan/security/advisories/new>

Отчёт виден только владельцу репозитория и выбранным участникам, пока мы не опубликуем advisory
после исправления. Если GitHub недоступен, напишите владельцу репозитория и попросите другой
приватный канал.

**Не открывайте публичный issue** с описанием уязвимости: это раскрывает проблему до исправления.
Публичный issue уместен только для вопросов, в которых нет деталей эксплуатации.

## Сроки

| Этап | Срок |
|---|---|
| Подтверждение получения отчёта | 72 часа |
| Первичная оценка и план исправления | 7 дней |
| Исправление high/critical | 30 дней |

Сроки — ориентир для поддерживаемой ветки. Если исправление затрагивает формат проекта или
бинарный контракт APK, согласуем дату выпуска отдельно и скажем об этом в отчёте.

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| 2.9.x (текущая — 2.9.1) | Да: исправления безопасности и обычные баги |
| 2.8.x и старше | Нет; только критичные исправления по решению владельца |

Мы не выпускаем патчи для старых веток: обновление до 2.9.x бесплатное, формат проектов
совместим (см. [RELEASE-NOTES-2.9.1.md](docs/RELEASE-NOTES-2.9.1.md)).

## Область действия

Что входит в поставку и что мы проверяем:

- **APK для Android** — офлайн-сборка. В манифесте единственное разрешение `VIBRATE`,
  `INTERNET` нет; `allowBackup=false`, `debuggable=false`, `usesCleartextTraffic=false`, JS-мост
  проверяет origin страницы.
- **Веб-сборка** — та же кодовая база на GitHub Pages (`enkolesnikov.github.io/AnOOPlan/app/`).
  Интересны XSS, обход CSP, подмена вложений при импорте проекта.
- **LAN-сервер** (`server/`, express) — запускается вручную через `npm start`. По умолчанию слушает
  `127.0.0.1`; LAN-режим требует токен `ANOOPLAN_TOKEN`, запросы без токена отклоняются.

Что в поставку **не входит**:

- `dsh/` — инструменты разработки (сборка/диагностика), в APK и на сайт не попадают. Их уязвимости
  не считаются уязвимостями продукта, но сообщить о них всё равно можно.
- `tests/`, `scripts/`, CI-workflow — полезны для качества, но не исполняются у пользователя.

## Что приложить к отчёту

- Версию AnOOPlan (номер в APK или `package.json`) и способ установки: APK, веб-версия, LAN-сервер.
- Версию Android/WebView или браузера.
- Шаги воспроизведения и, если есть, минимальный PoC: файл `.anooplan`, проект или запрос.
- Ожидаемое и фактическое поведение; оценку последствий.

## Чего делать не нужно

- Не присылайте реальные данные заказчиков: проекты, планы зданий, фотографии объектов, адреса.
  Для PoC достаточно синтетического проекта.
- Не публикуйте рабочий эксплойт и не проверяйте уязвимость на чужих данных и серверах.
- Не прикладывайте секреты и токены целиком — достаточно указать тип и место.
